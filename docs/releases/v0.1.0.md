# v0.1.0 — durable execution for LangGraph agents

First release. A crash in the middle of an agent costs one step, not the whole run.

The problem it solves, in one sentence: LangGraph's checkpointer tells you *which node* you reached,
not *whether that node already charged the customer*. Resuming from a checkpoint re-executes the
node, side effects included. This journals each step's **result** and replays it instead.

## Install

```bash
pip install "git+https://github.com/a643036114-sys/duragent.git#subdirectory=python"
pip install "langgraph>=0.2"          # to use the node wrapper
```

SQLite is the default and needs nothing. PostgreSQL:

```bash
pip install "psycopg[binary]>=3.1"
conn = connect("postgresql://user:pass@host/db")
```

## What is in it

- **Durable steps** — `(run_id, step_name)` is the claim key; a finished step replays its stored
  result and never calls your function again.
- **Approvals** — a gated node parks the run as `SUSPENDED` before the side effect. No thread is
  held, the process can exit, a human decides later. Optional `expires_in` deadline.
- **Budgets** — token, money, step and wall-clock caps. One conditional `UPDATE` checks and spends,
  so two workers cannot take the last cent twice. Raise the cap and the run continues from its
  current spend.
- **Retries** — exponential backoff stored as a `not_before` deadline; the run returns on schedule
  instead of whenever a lease happens to expire.
- **Workers** — claims, heartbeat, and takeover when a peer dies. Control-flow exceptions map to run
  states (`SUSPENDED`, `CANCELED`, scheduled, `FAILED`) rather than everything becoming a failure.
- **Input fingerprints** — `fingerprint=True` notices "same run, different input" and raises
  `InputChanged` instead of handing back work computed from something else.
- **Fork** — re-run from any completed step, keeping the history before it. Possible because the
  journal stores values, not opaque snapshots.
- **Diff** — compare two runs step by step using the outputs already stored.
- **Console, CLI, metrics** — one HTML page, `duragent runs|inspect|fork|diff`, and
  `/metrics` in Prometheus text format.

## What it does not promise

- **Not exactly-once.** The function runs at least once; its result is stored at most once. A crash
  between the side effect and the write re-runs the function. `journal.key("refund")` gives you an
  idempotency key to hand downstream and close that window.
- **Not production ready.** One author, `0.1.0`, no schema migrations beyond additive columns, and
  claiming is first-come by creation time. The sharp edges are listed in
  [`python/README.md#known-limitations`](https://github.com/a643036114-sys/duragent/blob/main/python/README.md#known-limitations).
